# OctoAcme Role Interaction Checklist

## Purpose
This checklist helps teams ensure proper communication and handoffs between roles throughout the project lifecycle. Use this to verify that all necessary role interactions occur at key project milestones.

---

## Project Initiation Phase

- [ ] **Stakeholder/Sponsor + Product Manager**
  - [ ] Business case and objectives defined
  - [ ] Success metrics agreed upon
  - [ ] Budget and resource approval obtained

- [ ] **Product Manager + Project Manager**
  - [ ] Project scope and timeline discussed
  - [ ] High-level milestones identified
  - [ ] Stakeholder communication plan created

- [ ] **Stakeholder/Sponsor + Project Manager**
  - [ ] Project charter reviewed and approved
  - [ ] Decision gate sign-off obtained

---

## Planning Phase

- [ ] **Product Manager + Developers + Technical Architect**
  - [ ] Backlog created and prioritized
  - [ ] Acceptance criteria defined for top items
  - [ ] Technical feasibility assessed

- [ ] **Technical Architect + Project Manager**
  - [ ] Technical risks and dependencies identified
  - [ ] Resource estimates for architectural work obtained
  - [ ] Integration points with other systems documented

- [ ] **Product Manager + QA Lead**
  - [ ] Definition of Done (DoD) established
  - [ ] Test strategy and approach defined
  - [ ] Quality criteria documented

- [ ] **Project Manager + Scrum Master**
  - [ ] Sprint length and cadence agreed
  - [ ] Team capacity and velocity baseline established
  - [ ] Ceremony schedule finalized

- [ ] **Product Manager + Design/UX Lead**
  - [ ] User research findings shared
  - [ ] Design system and patterns reviewed
  - [ ] UX specifications drafted for key features

---

## Execution & Sprint Phase

### Daily/Continuous Interactions

- [ ] **Scrum Master + All Roles**
  - [ ] Daily standups held (blockers identified and addressed)
  - [ ] Team health and impediments tracked
  - [ ] Focus time protected from interruptions

- [ ] **Developers + QA Lead**
  - [ ] Test cases reviewed before development
  - [ ] Acceptance tests automated as features are built
  - [ ] Early QA feedback provided on implementation

- [ ] **Developers + Technical Architect**
  - [ ] Architecture decisions reviewed
  - [ ] Design patterns and best practices discussed
  - [ ] Technical debt identified and tracked

- [ ] **Developers + Design/UX Lead**
  - [ ] Design specifications clarified
  - [ ] Implementation aligns with design system
  - [ ] Accessibility requirements confirmed

### Sprint Review & Planning

- [ ] **Scrum Master + Product Manager**
  - [ ] Backlog refinement sessions scheduled
  - [ ] User stories estimated and prioritized
  - [ ] Sprint goal aligned with roadmap

- [ ] **Project Manager + Technical Architect**
  - [ ] Technical dependencies flagged for upcoming sprints
  - [ ] Risk register updated
  - [ ] Velocity used to forecast timeline

- [ ] **Product Manager + Stakeholder/Sponsor**
  - [ ] Progress against success metrics reviewed
  - [ ] High-level demo or update provided
  - [ ] Scope or priority changes discussed

---

## Quality & Testing Phase

- [ ] **QA Lead + Developers**
  - [ ] Test execution tracked
  - [ ] Defects logged and triaged
  - [ ] Acceptance criteria verification completed

- [ ] **QA Lead + Product Manager**
  - [ ] User acceptance testing (UAT) scheduled
  - [ ] Feature completeness confirmed
  - [ ] User workflows validated

- [ ] **QA Lead + Technical Architect**
  - [ ] Performance and security tests designed
  - [ ] Load testing and scalability validated
  - [ ] Technical quality gates met

- [ ] **QA Lead + Release Manager**
  - [ ] Release readiness checklist completed
  - [ ] Smoke test plan finalized
  - [ ] Rollback procedures documented and tested

---

## Release & Deployment Phase

- [ ] **Release Manager + All Technical Roles**
  - [ ] Pre-deployment checklist reviewed
  - [ ] Code freeze communicated
  - [ ] Deployment plan finalized

- [ ] **Release Manager + Project Manager**
  - [ ] Release date confirmed and communicated
  - [ ] Deployment window scheduled
  - [ ] Stakeholder notification plan confirmed

- [ ] **Release Manager + QA Lead**
  - [ ] Smoke tests conducted on staging
  - [ ] Post-deployment verification plan ready
  - [ ] Known issues and workarounds documented

- [ ] **Release Manager + Stakeholder/Sponsor**
  - [ ] Launch announcement prepared
  - [ ] Customer communication approved
  - [ ] Go/no-go decision confirmed

---

## Post-Release & Retrospective Phase

- [ ] **Release Manager + All Roles**
  - [ ] Post-deployment monitoring completed
  - [ ] No critical incidents outstanding
  - [ ] Release metrics captured (deployment time, issues, etc.)

- [ ] **Scrum Master + All Roles**
  - [ ] Retrospective scheduled within 2-3 days of release
  - [ ] What went well and improvements discussed
  - [ ] Action items assigned with owners and due dates

- [ ] **Project Manager + Stakeholder/Sponsor**
  - [ ] Project closeout checklist completed
  - [ ] Business value metrics reviewed
  - [ ] Lessons learned documented

- [ ] **Product Manager + Design/UX Lead**
  - [ ] User feedback collected post-launch
  - [ ] Usability metrics tracked
  - [ ] Backlog items created for improvements

---

## Cross-Functional Handoff Checklist

Use this quick checklist for any handoff between roles:

- [ ] **Information Shared**
  - [ ] Handoff document or email sent
  - [ ] Key decisions and rationale explained
  - [ ] Open questions or risks flagged

- [ ] **Acknowledgment**
  - [ ] Recipient confirmed receipt and understanding
  - [ ] Clarifying questions addressed
  - [ ] Next steps and timeline confirmed

- [ ] **Documentation**
  - [ ] Handoff recorded in project tracking system
  - [ ] Relevant links and artifacts attached
  - [ ] Follow-up date scheduled if needed

---

## Role-Specific Touchpoints

### Product Manager's Week

- [ ] Monday: Backlog refinement with team
- [ ] Tuesday/Wednesday: Design and UX review
- [ ] Thursday: Stakeholder sync
- [ ] Friday: Sprint review and planning for next sprint

### Project Manager's Week

- [ ] Daily: Standup facilitation (or async standup review)
- [ ] Monday: Risk register and dependency review
- [ ] Wednesday: Mid-sprint health check
- [ ] Friday: Status reporting to stakeholders

### QA Lead's Week

- [ ] Daily: Test execution and defect triage
- [ ] Monday/Thursday: Test planning and strategy sessions
- [ ] Wednesday: Release readiness assessment
- [ ] Friday: Quality metrics and trend reporting

### Release Manager's Week (Sprint Cycle)

- [ ] Early Sprint: Release planning and dependencies
- [ ] Mid Sprint: Readiness checks begin
- [ ] Late Sprint: Go/no-go decision criteria reviewed
- [ ] Release Week: Deployment execution and monitoring

---

## Communication Anti-Patterns (What NOT to Do)

- ❌ **Silos:** Developers building without QA involvement
- ❌ **Silent Failures:** Technical risks not escalated to PM
- ❌ **Surprise Releases:** No stakeholder notification before go-live
- ❌ **Scope Creep:** Changes approved without Product Manager
- ❌ **Quality Surprises:** Late discovery of defects in production
- ❌ **Missed Ceremonies:** Key roles absent from planning/review
- ❌ **Documentation Gaps:** Handoffs done verbally with no record

---

## How to Use This Checklist

1. **Print or share** this checklist with your project team at kickoff
2. **Customize** based on your team structure and project needs
3. **Review weekly** during project syncs to ensure interactions are happening
4. **Update** as roles or responsibilities change
5. **Reference** during retrospectives to identify gaps in collaboration
